# iOS app "Tài khoản" (`com.hoandat.account`)

Native SwiftUI app to manage an account of the IdP: profile, sign-in methods
(link/unlink Google, GitHub, Apple), browser sessions, devices, apps with
access, security notifications, Face ID app lock and account deletion. It
signs in through the system browser (`ASWebAuthenticationSession`) as the
public OIDC client `account-ios` and talks only to `/api/account`. Plan:
`plans/dattqh/261020-0742-ios-account-app/` (this is phase 04).

iOS 18+, iPhone only, Swift 6 language mode with complete concurrency
checking, no third-party dependencies. UI in English, Vietnamese and
Simplified Chinese.

## How it talks to the IdP

The full contract, with every endpoint, field and error code the app depends
on, is in [`contract/README.md`](contract/README.md). In short:

- Discovery → authorize (`state`, `nonce`, PKCE S256, `device_name`,
  `ui_locales`) → universal link `https://<issuer>/ios/callback` → code
  exchange → ID token claims checked (`iss`, `aud`, `nonce`, `exp`).
- Tokens live in one Keychain item, `AfterFirstUnlockThisDeviceOnly`, never
  in `UserDefaults`, never logged. `UserDefaults` holds only two booleans
  (app lock on, notifications on), as declared in the privacy manifest.
- Refresh is serialised by an actor: concurrent callers share one request,
  because refresh tokens rotate and are single-use.
- Sensitive actions (remove app access, sign out all browsers, link, unlink,
  delete) run `prompt=login`, switch to the new grant, revoke the old refresh
  token, re-register push, then send the fresh `id_token` once.
- Linking a provider is two steps: the browser sheet ends on
  `/ios/linked?result=pending&ref=…`, then the app completes it with its own
  bearer token (`POST …/link/complete`); only that answer is shown.
- Sign-out: `DELETE /api/account/push-device`, revoke the refresh token,
  clear the Keychain item. Deletion: `DELETE /api/account`, clear the item,
  sign-in screen shows "deleted".
- Offline: the last loaded account stays on screen under an offline notice;
  a refused refresh or a second 401 returns to sign-in with "session ended".

## Build and test

Requires Xcode 26 or later (CI pins 26.x; this was developed with 27.1).

```sh
# Unit tests on the Mac, no simulator needed (keep build output out of the repo,
# biome lints every JSON file under ios/):
cd ios/AccountKit && swift test --scratch-path "$TMPDIR/accountkit-build"

# App build without signing:
cd ios && xcodebuild build -project AccountApp.xcodeproj -scheme AccountApp \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath "$TMPDIR/AccountAppDD" CODE_SIGNING_ALLOWED=NO

# Everything (unit + UI tests) on a simulator, as CI does:
cd ios && xcodebuild test -project AccountApp.xcodeproj -scheme AccountApp \
  -destination 'platform=iOS Simulator,name=iPhone 17' CODE_SIGNING_ALLOWED=NO
```

CI: `.github/workflows/ios.yml` runs `xcodebuild test` on `macos-latest` with
the newest Xcode 26.x and an available iPhone simulator, whenever `ios/**`,
`src/account-api/**` or `src/oidc/account-ios-client.ts` changes.

After editing `project.yml`, run `xcodegen` in `ios/` and commit the project.
After editing an asset catalog in Xcode, run `pnpm exec biome format --write ios`
(Xcode writes JSON that `pnpm lint` rejects). New UI strings: add them to
`AccountApp/Resources/Localizable.xcstrings` with `vi` and `zh-Hans`.

## Running on a device

1. Phase 00 done: App ID `com.hoandat.account` with Push Notifications and
   Associated Domains, Sign in with Apple enabled on production.
2. `cp Config/Local.xcconfig.example Config/Local.xcconfig` (team AM5C55N339).
3. The IdP must serve `/.well-known/apple-app-site-association` with
   `IOS_APP_ID=AM5C55N339.com.hoandat.account` (phase 02) and know the client
   `account-ios`; otherwise the browser sheet never returns to the app.
4. Open `AccountApp.xcodeproj`, pick the device, Run. Development builds get
   sandbox APNs tokens, TestFlight/App Store builds production ones.
